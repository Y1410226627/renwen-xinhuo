# 术语表与措辞禁忌（GLOSSARY）

> 本文件是**给人看的**写作纪律表，与 `solve/guard.py` 的**机器护栏**互为表里：
> 护栏在**代码层**拦「数字无出处 / 引文未落地 / 边界声明缺失」；
> 本表在**写作层**先说清「哪些话我们不该说、为什么」。
> 由来：采用 `_Avoid_` 式写法——
> 每一条术语都注明**禁用的说法**与**理由**，避免反复踩同一类坑。
> 约定：**每条两行**——`术语`：一句话定义；`_Avoid_`：禁止的说法与原因。

---

## 一、形式与声调

**平 / 仄**：本系统按**普通话四声**折算——阴平、阳平记平，上声、去声记仄。
`_Avoid_`：**不可写成「平声＝平调＝舒缓、仄声＝仄调＝急促」**。平仄是**声调类别**，不是**情绪**，也不是音响学上的音高曲线。

**仄声比例**：一篇之内，仄声字数 ÷ 全篇汉字数（百分比，**Python round 银行家舍入**，保留一位小数）。
`_Avoid_`：**不可写成「仄声越多越悲壮/越激昂」**。比例只反映**文本的形式配置**，不承载情感判断。

**变化 / 绝对变幅**：一篇**后半段与前半段**仄声比例的差（`后段 − 前段`，百分点）。
`_Avoid_`：**不可写成「情绪走势」「情感转折」**。它是**文本结构的数值差**，且受分行口径影响——只能读作「后段比前段的仄声配置高/低多少」。

**声情**：语料**自带的标注字段**（如「后段上升」），是**整理本已给的标签**，不是本系统推断的。
`_Avoid_`：**不可写成「本系统分析出这篇的情感基调」**。必须说「据语料标注」，并声明「不能据此推断作者意图」。

**声律转向（本系统**实际计算**的那一层）**：确定性引擎真正算的是「后段仄声比例 − 前段仄声比例」
的符号方向（上升／下降／持平），即 `prosody.scene_emotion()`。
`_Avoid_`：**不可把「后段上升」说成「情绪转浓／情感升华」**，也不可宣称本系统做了「情感识别／情感分析」。
本系统的**确定性层只到声律**；任何涉及情感、意象、主题的判断都属于**第二层（辅助分析）**，
必须显式标注「非作者心理事实、非金标准、仅作候选」——**两层不得混为一谈**（外部审查 §63 的落点）。

**句脚 / 句末点**：句子的最后一个字；「句」按 `。？！` 切分。
`_Avoid_`：**不可写成「韵脚」**。句脚是**断句位置的字**，是否押韵要看**韵部**，本系统不判韵。

**入声字**：本系统**不单独标注入声**——一律按普通话折平仄（如「一/十/白/石」记**平**）。
`_Avoid_`：**不可声称「按平水韵」「按中古音」「入声归仄」**。这是**普通话口径**，与词律学的传统记法**可能不同**（长→cháng、别→biè、绝→仄 三字为本语料已生效的覆写例外）。

**评测口径 / 学术口径（双口径声明）**：本系统当前**只实现「评测口径」**——普通话四声折平仄、
不注入声、不划韵部、不做简繁校勘；它服务于**可复现的确定性评测**。
`_Avoid_`：**不可把评测口径的结论当作词律学的学术结论**。真正的研究还需入声、词韵、韵部、古音、
词牌格律校勘等（本系统**未实现**）。若将来引入，必须作为**并存的新口径**（见第五节「口径」条），
**不得就地修改评测口径**——否则既有数字将失去可解释性（外部审查 §64 的落点）。

## 二、检索与统计

**命中篇数（真值）**：满足全部**硬条件**的篇数，逐篇比对的**确切计数**（不是 top-k、不是召回数）。
`_Avoid_`：**不可写成「召回 N 篇」「找到 N 首」（当 N 是 top-k 时）**。展示 3 篇时必须另注「此处展示前 3 篇」，并给出真实命中篇数。

**词面**：问句里**未被识别为结构化条件**的汉字串，用于**文本相关度**检索（二字组短语）。
`_Avoid_`：**不可把「词面命中」说成「按条件命中」**。词面只是相关度信号，**不构成筛选条件**。

**题名 / 词题 / 词牌**（三者**不同**）：
- **词牌**：词调名（如「蝶恋花」），是可检索的元数据；
- **题名**：完整标题（如「蝶恋花·清明同诸子集原白斋中」）；
- **词题**：题名里**词牌之后**的部分（如「清明同诸子集原白斋中」）。
`_Avoid_`：**不可把「题名」当「词原文（正文）」检索**——这是本系统 2026-10-05 修掉的缺陷（实测：「清明同诸子集原白斋中」在正文里 0 命中，它是**题名**）。题名要用**题名条件**检索。

**融合排序（融合分）**：五路检索（词面/元数据/全文/数值/声律模式）加权后的排序。
`_Avoid_`：**不可把「融合排序最前者」说成「最符合的答案」**——它只是**未给结构化条件时**的相关度排序**代表篇**，不代表语义/评价/优劣。

## 三、结论与边界

**数值型问句**：答案为数字（篇数/比例/中位数/极值）的问句。
`_Avoid_`：**不可替用户下因果结论**（「因为…所以…」），不可作优劣判断（「更好/更美」）。

**意图型问句**：问「作者想表达什么 / 中心思想 / 为什么这样写」这类**语义层面**的请求。
`_Avoid_`：**不可用检索结果冒充答案**。本系统**不做**语义理解，应显式认账（「现有语料未见支持」），并引导用户指明篇目后自审。

**因果型 / 优劣型问句**：问「为什么（历时的/社会的因）」或「哪个更好」。
`_Avoid_`：**不可回答推断性、评价性结论**。数值可给，**推断不给**——四类边界声明互斥，必须与问句类型匹配。

**拒答**：按官方与工程纪律，**给不出确切答案时如实说出**，而不是拿相近的凑数。
`_Avoid_`：**不可说「语料中没有这首词」**——须区分三种「没有」：
- **语料外范围**（如唐诗）＝**不支持**（本系统只有清/宋/元词）；
- **范围内 0 篇**＝**确切结果 0**（这是一个答案，不是失败）；
- **范围非空但该口径无可用数据**（分组样本不足/指标缺失）＝须报**真实命中篇数**再说清「按该口径不给该统计量」。

**待核 / 存疑**：本语料的平仄来自**覆写表 + 标定表 + 多候选取首**，**不是逐字校勘本**。
`_Avoid_`：**不可宣称「全部经学术校勘」**。凡走了覆写、多候选、残片（0 句/0 字）的篇目，都属于**可存疑**，应能被单独列出（见 `tools/uncertainty_report.py`）。

## 四、出处与引用

**证据块 [E1]/[E2]**：检索返回的篇目证据，含出处 pid 与引擎算出的数字。
`_Avoid_`：**不可在引文里改动任何一个字**（含标点）——引用必须**逐字整句**落地，引号内只能是语料原文。

**出处 pid**：`文件名#数组下标`，可点回语料原文（`poetry-source` 为清词主源；`chinese-poetry` 为宋/元源）。
`_Avoid_`：**不可把 pid 当作学术引证编号**。本系统**据公开整理本复算**，**不作学术引证**。

## 五、论证与判断的分层（2026-10-13 新增）

> 由来：自查发现「论证辅助」**本质只是切换任务提示**，且「**数字曾出现，不等于它支持当前句子的
> 具体论断**」。为此把论证从「一段散文」升级为**结构化论证稿**（`solve/gen.py`），
> 并给每条分论点强制要求下列字段。
> **措辞纪律**：这些字段名是**机器契约**（`parse_argument` 会校验），写作时不得随意改义。

**主张（thesis / claim）**：一篇论证稿的**总论点**，以及每条**分论点**。
`_Avoid_`：**不可把「形式事实」直接写成「结论」**——如不得由「仄声比例 60%」直接断言「情感悲壮」。
形式事实只能作为**证据**，不能冒充**判断**。

**桥梁（bridge）**：从**形式事实**到**该判断**的**推理依据**——**每条分论点必填**（缺则整稿丢弃）。
`_Avoid_`：**不可省略、不可写成同义反复**（如「因为仄声多，所以仄声多」）。桥梁要说明**为什么**这个形式特征能支持这个判断，以及**在哪一层**成立。

**评估态（assessment）**：本系统对该分论点的**置信程度**，四值之一：
- `supported` 证据直接支持；
- `mixed` 部分支持、部分相悖；
- `insufficient` **证据不足**（此时 `gaps` 必须非空）；
- `unresolved` **现有材料无法判定**（此时 `gaps` 必须非空）。
`_Avoid_`：**不可用「一定」「必然」这类词替代评估态**。评估态是**机器可读的自陈置信**，不是修辞。

**替代解释（alternatives）**：对同一现象**另一种可能的读法**。
`_Avoid_`：**不可把一种解读说成唯一答案**——尤其当证据只能支持到形式层时。

**缺证（gaps）**：要让该主张更可靠，**还缺什么证据**。
`_Avoid_`：**不可用「有待进一步研究」这种空话充数**——须写明**缺哪一类材料**（如「缺原书影像校勘」「缺该调第二个体式的谱式」）。

**数字可追溯性（traceability）**：每个数字的**来源等级**——`cited`（可追到本行 `[E#]` 引用块，强）
／ `global`（仅凭「全库证据块合法值」放行，**弱**）／ `allowed`（查询条件等非论断性来源）／ `none`（无出处）。
`_Avoid_`：**不可因为「数字在库里出现过」就认为它支持当前这句话**。`global` 级数字**必须人工复核**——
这正是形式层证据的软肋，本系统用 `guard.audit_number_traceability()` 如实分级、不隐瞒。

## 六、核验深度分层（2026-10-13 新增）

> 由来：核验有深浅之别，一条结论必须说清**核到哪一层**。
> 此前只有「待核 / 存疑」两档，容易把不同深度混为一谈。现补齐这条纪律。
> **一句话**：**「来源对上了」不等于「底本核过」，更不等于「语境读音定了」。**

**① 数字转录一致（source_matched）**：正文与来源转录**逐字相符**（我们与来源两处一致）。
`_Avoid_`：**不可说成「已校勘」「定本」**。它只证明「我们的录入没错」，**不证明来源本身对**。

**② 来源准入（admitted）**：该作品来自**已登记的可信来源**（provider + commit + 文件 hash 通过）。
`_Avoid_`：**不可说成「学术核验完成」**。来源是公开整理本，**不是原书影像**。

**③ 底本校勘（text_collation）**：与**原书影像**逐字核对。
`_Avoid_`：**本系统当前一律为 `unverified`**——凡声称「已核原书」都是假的。词谱数据同理
（「搜韵公开转写（**未核原书**）」是常驻红线）。

**④ 语境读音裁定（人工选读）**：研究者为**某个字位**选定读音并记录依据。
`_Avoid_`：**不可把「一处选读」扩散到同字的其它位置**（字位分开是硬纪律）；
也不可由「合律」反推读音（合律不能代替语境裁定）。

**⑤ 单篇创作年代**：该作品**确作于何时**。
`_Avoid_`：**不可由「来源目录标『清』」推出「确作于清」**——来源时代标签 ≠ 单篇年代考证。
本系统当前一律 `unverified`。

**⑥ 形式事实 / 规范比较 / 推断 / 学术解释（四层）**：
形式事实（引擎算的数字）→ 规范比较（actual vs expected）→ 推断（本次解释）→ 学术解释（署名文献观点）。
`_Avoid_`：**不可把四层压成一句结论**。尤其是**不可由「形式事实」直接跳到「学术解释」**——
中间必须有**桥梁**（见第五节「桥梁」条），否则整稿丢弃。

## 七、元：关于本表自身

**口径（profile）**：一组冻结的「参数包」——四声→平仄策略、覆写表版本、舍入策略、排序策略、简繁转换策略。
`_Avoid_`：**不可静默改动口径**。口径变即**新增**口径（保留旧口径），否则「旧数字」会失去可解释性。
