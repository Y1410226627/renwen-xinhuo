## D01 汉字判定口径：基本区 + CJK 扩展 A

- **决定**：一个字符算「汉字」当且仅当它在 `\u4e00-\u9fff`（基本区）**或** `\u3400-\u4dbf`（扩展 A）。占位符 □ ○ ■ 不计。
- **理由**：题库实测口径 ≠ 任务书原文（任务书未提扩展 A）。
- **证据**：全量 700 公开 + 300 保密题按此口径复算零偏差。
- **状态**：✅ 已接受。**影响**：`prosody` 字长、平仄统计的基。

## D15 ✅ 已接受：前端改用 Vue3+Vite 组件化，但逻辑层「单一真源 + 薄适配」

- **决定**（2026-10-05）：
  1. 视图层由「Python 内嵌 HTML 字符串 + 手写模板 + 全局脚本」改为 **Vue3 组件化单页/多页应用**（Vite 构建），页面外壳统一走组件。
  2. **数据/逻辑层不做两份**：把 `metrics.js`（声律指标）、`ui.js`（转义/格式化/CSV/主题）、`app_parse.js`（判定表/分页/渲染）、`app_review.js`（筛选/排序）的**纯函数**收进 `frontend/src/core/*.js`，作为**唯一真源**。
  3. 仓库里**旧路径文件**（`web/metrics.js` 等）退化为**薄转发**：`module.exports = require('../frontend/src/core/xxx.js')`，并保留 `window.Xxx = api` 的 UMD 尾巴。
  4. 后端 `serve.py` **只换静态资源路由**，`/api/*` 端点**签名与字段一律不动**。
- **理由**：
  - 评审要「少 HTML、可维护」（老师原话：HTML 语言太多，别人接手难改）；
  - 但**最大风险**是「重写把已验证的正确性弄丢」——四道门禁（`test_ui/test_render/verify_views/test_api`）断言的正是这些纯函数与**字符串渲染契约**。
  - 「单一真源 + 薄适配」使 Vue 组件与 node 门禁**共用同一份实现**，既拿框架之利，又**零实现漂移**；门禁断言值**一字不改**。
- **被拒绝的备选**：
  - ❌ 把逻辑整体搬进 `.vue` 的 `<script setup>` → node 门禁**无法加载**，`detailHtml` 字符串契约与 12 条标尺立刻失守。
  - ❌ 逻辑层写两遍（Vue 一份、测试一份）→ 必然漂移，等于把「同一个 bug 修一半」的风险制度化。
  - ❌ 不用框架、只把内嵌 HTML 抽成 `.html` 文件 → 治标不治本，组件复用/状态管理仍缺，老师指出的「维护难」未解决。
- **影响**：`frontend/`（新，Vue 源码）＋ `data/vue/`（构建产物，页面就地可开）＋ `web/serve.py`（静态路由）。
  改 `frontend/`、`web/serve.py`、`web/build_views.py` **均在结构性隔离之外** → 双集哈希不变（见 D07）。
- **落地结果**（2026-10-05 实测）：
  - 6 个视图全部 Vue 组件化：`IndexView / AskView / ParseView(离线+在线双模) / GraphView / ReviewView`，外加外壳 `AppShell`。
  - 逻辑层搬家等价性：`frontend/tools/check-core.cjs` **213,972 项 0 不符**（与冻结基线逐字节）。
  - 四道门禁全绿：`web/test_ui.js` 130 项、`web/test_render.js` 26742 篇/522,242 项、
    `web/verify_views.js` 43,459 项、`web/test_api.py` 140 项 —— **全部 0 不符**；
    SSR 组件冒烟 26 项 0 不符。
  - 双集哈希不变：公开 `BF863368…`、第二套 `ACEF8B15…`（`tools/regress.py` 各 28 项全过）。
  - 端到端：`python web/serve.py` 下 6 个页面与全部引用资源 200，`/api/ask_stream` 事件序 `status→status→final→done`。
- **构建顺序（易踩坑）**：Vite 的 `emptyOutDir` 会清空 `data/vue/`，而 `pack.js/graph.json/rev.js`
  由 Python 生成在同一目录。**必须先 Vite、后 Python**；已固化为 `npm run build:all`
  （`frontend/tools/build-all.mjs`：① 构建离线视图 → ② 构建问答页 → ③ 生成数据）。
- **Windows 依赖坑**：`esbuild` / `@rollup/rollup-win32-x64-msvc` 的 postinstall 在 Git Bash 下会 spawn 失败，
  安装需 `--ignore-scripts` 并手工补 `--save-optional` 平台包；`npm` 是 shell 脚本，
  用 node 跑须指向 `node_modules/npm/bin/npm-cli.js`。
- **⚠ 两个「看不见的坑」（2026-10-05 排查实录，务必保留）**：
  1. **`cleanStale` 判据写反，把刚构建好的页面删了**。`emptyOutDir:false` 规避了宿主安全删除护栏后，
     需要在 build-all 里自己清陈旧文件。初版写的是「构建前快照，构建后把快照里仍存在的都删」——
     但 Vite 是**覆盖写**同名文件，构建后 `parse.html` 依然在，于是被判为「陈旧」删掉，
     结果 `data/vue/` 五个 HTML 全没，`web/test_ui.js` 直接 ENOENT 崩。
     **正确判据**：构建后重新快照，只有「上轮有、本轮**没有**」且属于 **Vite 专属产物**
     （`assets/**` 与 5 个 html）的文件才删；Python 生成的数据文件绝不进删除清单。
  2. **`pythonExe()` 探测在子进程环境不稳**。`spawnSync('python', ...)` 在 `reproduce.py`
     的子进程里偶发失败（PATH 继承 / 宿主护栏拦截探测），误报「找不到 python」，
     而绝对路径解释器明明是好的。**正确做法**：① 先认 `LVC_PYTHON` / `PYTHON` 环境变量
     （`reproduce.py` 已用 `pick_python()` 挑好，传给 node 步骤即可）；② 绝对路径先 `existsSync`
     再 `spawnSync`，并区分「起不来」与「返回非 0」。
  3. **顺带修**：`build-all.mjs` 原缺 `import fs`（`snapshot/cleanStale` 里用到 `fs` 却未导入，
     靠 `try/catch` 静默吞掉——即清理功能一直是空转的死代码，这也是坑 1 潜伏至今没暴露的原因）。
- **状态**：✅ 已接受。

  **D09 已采纳的 `rescue_title()` 通道拿不到输入** → 无语义条件 → 又回到答非所问。

## D23 ✅ 已修：题名条件无「存在性」校验 —— 模型/任何来源塞进来的坏题名直接导致 0 篇

- **现象**（2026-10-06 主人实测）：问「（承上一轮）江城子 忆梦中最长的一句是哪一句」，
  解析出「词牌=江城子；**题名=忆梦中最长的**；排序=最长句长度」→ 命中 **0 篇** →
  「本语料中没有作品同时满足」。而库里明确有 **清·柳如是《江城子·忆梦》**
  （`ci.清.0026.base.json#734`），且「忆梦中最长的」根本不是题名、是问句描述。
- **根因**：`title_any` 的**出口没有统一校验**。来源有二：规则路（「词牌·题名」识别，
  值来自语料原文，可信）与大模型路（`qlm.validate` 读的键里**根本没有 title**——
  其它字段都有「库中没有→丢弃」校验，唯独 title 缺失）。一旦任何路径把
  「问句描述」当题名塞进来，`title LIKE` 0 命中就把整个检索变成 0 篇。
- **修复（出口统一收口，`ask.py` 的 `understand` 返回后立即执行）**：
  对 `spec.title_any` 逐项做 `title LIKE` 存在性校验——**命中 0 的一律降级**：
  移出硬条件、降为词面（≥2 字），并如实披露（「题名「…」在语料标题中不存在，
  已降级为词面参与语义检索」）。这样无论未来再加多少条产生 title 的路径，
  出口都只放行「库里真实存在」的题名。
