## 二、【本遍新发现·低】`api.js` 的注释与事实不符（服务端**确实**发 `done` 帧）

- `api.js:214` 原注释称「服务端**根本不发送** `done` 帧（只发 status/engine/delta/final/error）」。
- **实读 `serve.py:1746`**：SSE 生成器末尾**确实** `yield 'data: {"type":"done"}\n\n'`。
- 影响：**行为正确**（分派按 `type`，`done` 帧在 `AskView` 的 handler 里落到无分支 → 静默忽略），
  但注释**误导后人**（让人以为不该出现 `done` 帧）。
- **修法**：更正注释——如实说明服务端会在末尾发协议级 `{"type":"done"}` 哨帧，
  语义上的"结束"由 `final`/`error` 承担，故传输层**只分派、不吞帧**。

## 四、【本遍新发现·低】`_derived_tables` 的 ATTACH 措辞不准（非 URI 只读）

- 原 docstring 写「侧车库（**只读** ATTACH 成 `dv`）」「把它 `ATTACH` 进来（**只读**、惰性）」。
- 实读代码 `:1924`：`conn.execute('ATTACH DATABASE ? AS dv', (p,))` —— 这是**普通 ATTACH**，
  不是 SQLite 的**只读 URI 模式**（语料连接 `get_conn()` 未开 `uri=True`）。
  即「不写侧车库」是**靠约定**（本模块只对它发 SELECT）而非引擎强制。
- 影响：**无功能危害**（三处用法 `title MATCH` / `SELECT pid FROM dv.pz_gram` 全是读取，
  无 `INSERT/UPDATE dv.*`），但措辞夸大了一个不存在的保证——与本项目"注释必须与代码一致"的纪律不符。
- **修法**：更正为「普通 ATTACH + 本模块只读它」，并写明"若要引擎级只读需换 `uri=True` + `mode=ro`，
  那是更大范围改动，不冒进"。
- 过程中一度**打坏 docstring**（漏闭合 `"""` → `SyntaxError`），已立即修回；`import` 复验通过。
