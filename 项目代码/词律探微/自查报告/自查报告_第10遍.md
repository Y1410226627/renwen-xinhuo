## 二、本遍复核确认「已正确/无需改动」项

| 位置 | 结论 |
|---|---|
| `serve.py _write_guard`（H2） | ① Content-Type 必须 json（跨站简单请求无预检的第一道闸）；② Origin 存在时同源（Host 或 localhost/127.0.0.1/[::1]）；无 Origin（curl/脚本）放行——**顺序正确**（预检失败不达，Origin 是真正后盾）✅ |
| `serve.py _do_POST` 边界 | 1MB 上限 413、JSON/UTF-8 校验 400、非对象 400、未登记路径 404、幂等 token ✅ |
| `serve.py _err`（M12） | 统一信封 `{ok:False, code, error:<str>}`；HTTP 码按业务/错误分流 ✅ |
| `serve.py _err_detail`（M11） | 默认只回**异常类型**，完整串仅 `LVC_DEBUG=1`；与 do_GET「不回吐 traceback」同政策 ✅ |
| `serve.py do_GET/do_POST` 收口（M13） | `finally: _close_readonly()`，长跑不攒句柄 ✅ |
| `retrieve.py order_pids`（M4） | 按**未舍入** expr 排序、`pid ASC` 并列决胜 → 确定性；`check_agg` 78/0 佐证「排序口径 ↔ 显示口径」一致 ✅ |

> 理论上「DNS 重绑定」可令 `Origin` 与 `Host` 同为攻击者域名而放行；但服务**默认只绑 127.0.0.1**、
> 定位为本地单机工具，且审查报告 H2 的要求即「同源（Host 或 localhost）」，**已按规格落实**，不额外扩面。
