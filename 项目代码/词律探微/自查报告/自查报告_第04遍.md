## 三、【本遍新发现】护栏③的中文数字检测：**两处真问题 + 我们自己的拒答文案踩雷**

### 3.1【中】超长问句的拒答文案**被自己判为未通过**（本轮 M3 修复引入的回归）

- 现象：`ask.py` 超长拒答文案原文是「问句过长（**超过五百字**）。…请把问题拆成一句一条件…」。
- M3 给护栏③加了中文数字检测后，该文案里的 **「五百」被扫到** → `verify=False`，
  `problems=['拒答文本里仍出现中文数字（五百）…']`。
- **实测**（改前）：`A.answer(conn, '清'*600)` → `refused=True` 但 `verify=False`。
  UI 会把一次**完全正确**的拒答渲染成「护栏未通过」——把「系统行为正确」说成「系统有问题」，
  方向的错误与 M9 同类（把"没问题"说成"有问题"更该避免误导）。
- **修法**：文案改为**不含任何数字**（「超过本系统上限」），并去掉示例里的「一句一条件」
  （「一句」会被下面 3.2 的新检测误判），改为「拆开、逐条给出条件」。
- **复测**：`A.answer(conn,'清'*600)` → `verify=True, problems=[]`。✔

### 3.2【中】单字中文数字（「约三成」）仍能绕过护栏③

- `CN_NUM_RE = [零一二三四五六七八九十百千万亿两]{2,12}` **要求长度 ≥2**；
  `_cn_values('三')` 返回空集、`findall` 根本扫不到 → 「约三成」「八倍」「共两处」**全部绕过**。
- M3 的注释自称能拦「约三成」，**实际做不到**（注释与实现不符）。
- **修法**：新增**限定上下文**的单字检测 `CN_ONE_NUM_RE`——
  `[零一二三四五六七八九十两](?=[成倍篇首个条句字位名处次种分层档])`：
  只有「单个中文数字**紧跟量词/单位**」才算量化断言；「三更」「两宋」这类
  「数字+名词」不会命中。该检测**只在 `check_no_support`（拒答语境）里启用**，
  不动护栏①的口径（避免影响正常答案）。
- **复测**：

  | 文本 | 期望 | 实测 |
  | --- | --- | --- |
  | 现有语料未见支持：约三成作品满足。 | FAIL | ✔ FAIL |
  | 现有语料未见支持：八倍于前，共两处。 | FAIL | ✔ FAIL |
  | 现有语料未见支持：三更时分，两宋之际。 | PASS | ✔ PASS（无误报） |
