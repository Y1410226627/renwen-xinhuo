# 作品报告 · 词律探微——清代词律声情智能研究助手

> 对应《参赛指南》七（一）初赛作品提交清单所要求的内容结构。
> 建议导出为 PDF 提交；本文件为同源 Markdown。

## 一、作品名称与概要

**作品名称**：词律探微——清代词律声情智能研究助手（榜题 4，常规榜题）

**背景分析**：清词研究长期依赖人工标注平仄、四声、韵部与情感判断，耗时且口径难统一；
"清代词律声情数据库"已完成大规模标注（2,639 位词人、58,851 首词作、400 余万字音标注），
但仍以**静态查询**为主，数据价值未被充分释放。

**相关工作**：通用大模型无法深入清代词律的专业维度（逐字平仄、句脚、声情转向的**可复算数字**）；
传统 RAG 依赖文档切块与文本相似度，对**结构化数值问答**（计数/区间/排序/分组）天然无力。

**特色描述**：本作品把词作声律做成**可复算的数字**，用**证据与原文**作答，让大模型只负责"说得通顺"。
核心是**查询计划（Query Plan）+ 多路检索 + 确定性计算 + 证据绑定 + 结果验证**的 Hybrid RAG 架构。

## 二、作品设计与实现

### 2.1 系统架构（三条链物理隔离）

```
solve/           交付链（答案唯一来源，不 import ask/retrieve）
  corpus / pronounce / prosody / solver / aggregate / pairing / official
ask.py           问答链：理解 → 检索 → 证据 → 四道护栏
retrieve.py      多路检索：词面 / 元数据 / 全文 / 数值 / 声律模式 / 向量
── 第二轮架构重构（默认关闭，按需启用）──
queryplan.py     Query Plan（执行真源）：LEAF_SCHEMA + 布尔过滤树 + 计划往返
planner.py       LLM 规划器：Prompt 由 IR 现场生成（消灭契约漂移）
plan_exec.py     计划执行器：22 算子 + Provenance DAG 溯源
context.py       服务端会话语境：完整结果集 + 指代分类 + EXACT/SEMANTIC 区分
vector_index.py  真向量语义检索（SQLite 为真源，向量为派生索引）
fusion.py        RRF 名次融合 + 可选精排
answer_verify.py 集合身份校验（五态）+ 聚合复算（三态）
entity_resolve.py 实体解析层（作者/词牌/题名收口）
```

### 2.2 所用大模型 / 框架

- 大模型：经**校内/国产 API** 调用（Qwen 等），用于①问题规划（Planner）②说法层成文；
  **不承担事实与数字生成**。
- 框架：**不依赖重型 Agent 框架**，以"受约束的 Plan-based Agent"实现（LLM Planner + 有限工具集 + 确定性执行器），
  避免自由 ReAct 的不确定与合规风险。
- 嵌入/精排：`llm_embed.py` 直连 OpenAI 兼容嵌入端点（4096 维）与 rerank 端点。

### 2.3 核心功能模块（对应榜题五项）

| 功能 | 实现 |
| --- | --- |
| ① 声律自动解析 | `pronounce.py`/`prosody.py` + `/parse.html`：逐字平仄、四声、句脚、声情转向 |
| ② 声情智能问答 | `ask.py` + `/api/ask`：条件解析 → 检索 → 证据块 → 护栏 |
| ③ 论证辅助生成 | `gen.py` 说法层 + 证据块 + `answer_verify`；**数字/引文不过护栏即整段回退模板** |
| ④ 校订建议队列 | `tools/review_diff.py` / `review_apply.py` + `/review.html`（1 万余工单，可筛选/导出/写回） |
| ⑤ 知识图谱导航 | `web/build_views.py` → `graph.json` + `/graph.html`（词人 ↔ 词牌二部图） |

### 2.4 技术路线与实现原理（问答链）

```
用户问题 → 安全护栏 → 理解（规则路 / LLM 规划路）
        → 检索（SQL 精确 + FTS 字面 + 向量语义 + RRF 融合）
        → 确定性计算（聚合/极值/分组/集合运算）
        → 证据块 [E#] + 溯源 DAG
        → 说法层成文（可选）
        → 四道护栏（数字出处 / 引用逐字 / 无据认账 / 类型化边界）
        → 集合身份校验（独立复算 vs 返回集）
        → 最终答案（不可验证则如实拒答并说明理由）
```

**关键设计取舍**：

1. **SQLite 是唯一事实源，向量只是派生索引**（manifest 绑定语料指纹 + 模型 + 版本 + 维度，任一不符即判不可用）；
2. **硬条件不等同于"死路"**：有硬条件时先得候选全集，再在候选集内做向量检索（受限检索），
   避免"全库 top-k 再过滤"把正确答案截断；
3. **未验证 ≠ 已验证**：语义类问题不存在可判定的完整命中集，验证状态如实标 `SEMANTIC_NOT_EXHAUSTIVE`；
4. **无效实体不删条件**：把"查无此人/此调"编译为恒假哨兵 → 结果集为空，而**不是**退化成全库查询。

## 三、作品测试与分析

### 3.1 测试方案

| 层次 | 工具 | 说明 |
| --- | --- | --- |
| 交付链回归 | `tools/regress.py` + `solve/eval.py` | 公开 700 题逐字节哈希，防回退 |
| 结构/安全自检 | `solve/selftest.py` | 235 项程序化断言 |
| 库级不变式 | `tools/invariant_check.py` | 15 类恒等式直接查库 |
| 前端门禁 | `check-core.cjs` / `test_render.js` / `test_ui.js` / `verify_views.js` | 逻辑等价、逐篇渲染、功能、逐字段对照 |
| 服务端门禁 | `web/test_api.py` | 检索/理解/成文/对比/问答/解析 |
| **开放措辞基准** | `tools/nl_benchmark.py` | **独立 SQL 真值**（非引擎自证循环），40 条改写问法 |
| 计划层 | `solve/queryplan.py` / `plan_exec.py` / `planner.py --selftest` | 布尔树编译 vs 独立复算、多步执行 vs 独立复算 |
| 一键复现 | `reproduce.py` | 全流程并把**实际输出**写进 `复现报告.md` |

### 3.2 测试环境

Python 3.10+（开发用 3.11/3.14）；SQLite3（含 FTS5）；Node 22（前端门禁）；
Windows / Linux 均可；问答网页**只依赖 Python 标准库**。

### 3.3 测试数据

- 语料：清 26,742 / 宋 21,053 / 元 11,057，合计 **58,852 篇**、**420,476 句**；
- 公开题面：`数据/初赛数据/…/公开测试集_700题.jsonl`；
- 开放措辞基准：`tests/nl_paraphrase.jsonl`（40 条）+ `tests/nl_baseline.json`（冻结基线）。

### 3.4 结果分析（本轮实测）

| 项 | 结果 |
| --- | --- |
| `solve/selftest.py` | **235 项 0 失败** |
| `tools/regress.py`（公开集） | **PASS**（含期望哈希） |
| `reproduce.py --skip-build --quick` | **13 / 15 步 PASS**（余 2 项为既有口径分歧，非缺陷） |
| 开放措辞基准 · 默认链路 | 20/40（条件覆盖 27/40、计数 2/5） |
| 开放措辞基准 · 查询计划路 | **28/40**（条件覆盖 33/40、集合身份 20/29、**计数 5/5**） |
| 计划层自检 | `queryplan` / `planner` / `plan_exec`(15 项) / `context` / `answer_verify` **全过** |

**结论**：确定性查询（计数/区间/排序/分组/声律/出处）稳定可靠；
查询计划路对**开放措辞**（跨值 OR、否定、排除、计数、题名变体）有显著增益（+8 项），
个别题型仍待逐条消解（已在 `DECISIONS.md` D27 如实记录）。

## 四、创新性说明

1. **原创性**：查询计划 IR（`queryplan.py`）、计划执行器与溯源 DAG（`plan_exec.py`）、
   受限向量检索与 RRF 融合、集合身份验证器（`answer_verify.py`）、会话语境与结果集语义区分（`context.py`）
   均为本项目自研；声律解析口径与标定表为本项目整理。
2. **合规性**：全部使用公开整理语料（poetry-source / chinese-poetry）；不含个人信息与涉密材料；
   不使用境外模型与智能体工具；密钥不入库（模板 `llm_local.example.json`）。
3. **知识产权**：按《参赛指南》第十条，作品知识产权归学校与作者共同享有；本作品为原创，未参与其他竞赛。

## 五、总结

本作品把"数据丰富、利用不足"的清词声律数据库，升级为**可对话、可复算、可溯源**的智能研究助手：
- 对研究者：输入词作即得逐字平仄、四声、韵脚与声情分析；
- 对教学：提供可溯源的声情问答与论证辅助；
- 对数据库建设：校订建议队列形成标注闭环。

后续方向：把"规则候选 + 模型候选 → 仲裁"（Phase 4）做成默认理解层，逐条消解开放措辞基准中的剩余失手项。
