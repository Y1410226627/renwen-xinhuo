# 部署方案（单机 / 主从式 / 信创）

> 适用版本：`VERSION` 1.0.0 ｜ 目标：把本引擎放到一台**常开机器**上，供局域网 / 校园 VPN / 内网使用；
> 或作为**只读数据服务**挂在另一个主应用后面（主从式）。
> 只想本机自己用，看 `使用说明.md`「30 秒上手」即可，不必读本文。

---

## 一、本引擎的部署特征（为什么它好部署）

| 项 | 事实 |
| --- | --- |
| 运行时 | **Python 3.10+ 标准库**（`web/serve.py` 只用标准库） |
| 数据 | **SQLite 文件库**（`data/corpus.db` 只读 + `data/research.db` 读写）——**不需要数据库服务** |
| 出网 | 配置向量索引与嵌入端点后，主题类查询默认会把查询词发往该端点；设 `LVC_VECTOR=0` 可关闭。大模型说法层另行按需调用 |
| GPU | **不需要** |
| 可选增强 | 向量检索需 `faiss-cpu` + 嵌入端点；**缺装自动降级并如实说明**，其余功能不受影响 |
| 监听 | 默认 `127.0.0.1:8000`（端口被占**自动顺延**，以启动日志为准） |

> **一句话**：**只要机器上有 Python 3.10+，把目录拷过去就能跑。**

---

## 二、三种部署形态

| 形态 | 适用 | 要点 |
| --- | --- | --- |
| **A. 单机直连** | 本机 / 单人研究 | `python web/serve.py`（默认只绑 127.0.0.1） |
| **B. 局域网共享** | 内网 / 校园 VPN | `--host 0.0.0.0` 启动时也必须配置 `LVC_WRITE_TOKEN`；可提供远程读取，写操作只允许本机 HTTPS 反向代理转发 |
| **C. 主从式**（推荐用于对外服务） | 与另一个主应用共存 | 本引擎只绑 `127.0.0.1`，由**反向代理**按路径转发；主应用与本引擎**各用各的端口**，互不侵入 |

> **不要**把 `127.0.0.1` 当对外地址——它只在服务器本机有效。

## 三、主从式部署（形态 C）——推荐

### 3.1 架构

```
                    ┌───────────────────────────────┐
  浏览器 / 评委 ────▶│  反向代理（nginx / Caddy）      │
                    └───────┬───────────────┬───────┘
                            │               │
                 /  → 主应用 │               │ /engine/ → 本引擎
                            ▼               ▼
                 ┌──────────────────┐  ┌──────────────────────────┐
                 │ 主应用（:8000）    │  │ 词律探微引擎（:8010）      │
                 │ 自有数据库/框架    │  │ Python 标准库 + SQLite    │
                 └──────────────────┘  │ corpus.db（只读）          │
                                       │ research.db（读写）        │
                                       └──────────────────────────┘
```

**设计要点**：
1. **本引擎只绑 `127.0.0.1:8010`**，不直接对外——所有外部流量经反向代理；
2. **路径前缀 `/engine/`** 由代理剥掉后转发（`proxy_pass http://127.0.0.1:8010/;` 末尾的 `/` 会剥前缀）；
3. 主应用的**静态资源**（`data/vue/`、`web/dist/`）也可由代理直出，减轻引擎负担；
4. 两边**各用各的端口与数据**：本引擎的 SQLite 与主应用的数据库互不影响。

> **为什么不用「把引擎改成主应用的子模块」**：本引擎的立身之本是「零服务依赖 + 只读语料」。
> 保持**进程隔离**，既能沿用主应用的账号/网关，又不会让引擎的写接口暴露到主应用的路由里。

### 3.2 端口与路径规划（可直接照抄）

| 用途 | 端口 | 路径 | 备注 |
| --- | --- | --- | --- |
| 主应用 | 8000 | `/` | 由主应用负责 |
| 本引擎 | **8010** | `/engine/` | 只绑 127.0.0.1 |
| 反向代理 | 80 / 443 | — | 对外唯一入口 |

> 本引擎默认端口 8000；主从式下**显式指定 8010**，避免与主应用撞端口。

## 四、配置与启动

### 4.1 单机 / 局域网（形态 A、B）

```bash
# 形态 A：本机
cd <项目目录>
python web/serve.py

# 形态 B：局域网只读（0.0.0.0 = 监听所有网卡；远程 POST 会被拒绝）
# 先设置至少 32 个字符的随机令牌，并通过安全渠道交给授权使用者
export LVC_WRITE_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
printf '把此令牌通过安全渠道交给授权使用者：%s\n' "$LVC_WRITE_TOKEN"
python web/serve.py --host 0.0.0.0 --port 8000 --no-open

# 本机自测（应返回 JSON）
curl http://127.0.0.1:8000/api/examples
```

### 4.2 主从式（形态 C）

```bash
# 引擎只绑回环，交给 HTTPS 反向代理
# nginx 会传 X-Forwarded-For；设置令牌后代理写请求必须认证
export LVC_WRITE_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
printf '把此令牌通过安全渠道交给授权使用者：%s\n' "$LVC_WRITE_TOKEN"
python web/serve.py --host 127.0.0.1 --port 8010 --no-open
```

反向代理配置见 **`deploy/nginx-cilv.conf`**（含 `/engine/` 前缀转发、静态资源直出、
SSE 关闭缓冲、上传体积上限）。

该 nginx 示例只监听 HTTP/80；远程写请求会因未经过 HTTPS 而被拒绝。需要启用研究库写操作时，
请使用与引擎同机的 HTTPS/TLS 反向代理，并传入 `X-Forwarded-For` 与 `X-Forwarded-Proto: https`。
引擎只信任来自本机回环地址的代理连接；直连客户端即使伪造这些请求头也不能执行远程写入。

### 4.3 常驻服务（systemd，通用）

见 **`deploy/cilv-engine.service`**。主从式代理会传递 `X-Forwarded-For`，因此需先创建权限受限的
`/etc/cilv-engine.env`，内容为 `LVC_WRITE_TOKEN=<至少 32 字符的随机值>`，
并设置 `chmod 600 /etc/cilv-engine.env`：

```bash
sudo cp deploy/cilv-engine.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now cilv-engine
systemctl status cilv-engine
```

**Windows Server**：用「任务计划程序」时，在启动脚本中先设置 `LVC_WRITE_TOKEN`，再运行服务；
令牌至少 32 个随机字符，不要写入仓库或公开日志。浏览器端首次写入需输入相同令牌。

## 五、信创（openEuler / 麒麟）适配清单

> 结论先行：**本引擎依赖极轻，上信创的工作量主要在三处「确认」，而不是「改造」。**

| # | 事项 | 要做的事 | 失败后果 |
| --- | --- | --- | --- |
| 1 | **Python 版本** | 确认 `python3 -V` ≥ 3.10（openEuler LTS / 麒麟通常自带 3.9–3.11） | 低于 3.10 需装新版（`dnf install python3.11` 或源码编译） |
| 2 | **SQLite 的 FTS5** | `python3 -c "import sqlite3;c=sqlite3.connect(':memory:');c.execute('CREATE VIRTUAL TABLE t USING fts5(x)');print('FTS5 OK')"` | 未启用 FTS5 → **字面检索降级**（需换发行版自带的 CPython 或用 `pysqlite3-binary`） |
| 3 | **中文字体** | 装 `wqy-zenhei` / `noto-serif-cjk`（页面用楷体/仿宋，缺失时回退宋体/衬线） | 生僻字显示为方块 |
| 4 | **faiss-cpu**（可选） | 能装则装；装不上**不用管**——向量路自动降级并如实说明 | 无语义检索，其余功能正常 |
| 5 | **防火墙** | `firewall-cmd --add-port=8010/tcp --permanent && firewall-cmd --reload`（主从式下若只走代理可**不放行**） | 外部访问不通 |
| 6 | **时区/编码** | 确保 `LANG`/`LC_ALL` 为 `*.UTF-8`（中文路径与日志） | 中文文件名/日志乱码 |

**一键自检**（部署后先跑这个）：

```bash
python tools/check_all.py --fast      # 交付答案 SHA256 + 自检（约 10–20 秒）
python web/serve.py --port 8010 --no-open &   # 起服务
curl -s http://127.0.0.1:8010/api/examples | head -c 120
curl -s "http://127.0.0.1:8010/api/ask?q=%E6%B8%85%20%E4%B8%B4%E6%B1%9F%E4%BB%99%20%E4%BB%84%E5%A3%B0%E6%AF%94%E4%BE%8B%E9%AB%98%E4%BA%8E45%25" | head -c 200
```

## 六、数据与安全（部署时必须守的）

| 红线 | 说明 |
| --- | --- |
| **`data/corpus.db` 只读** | 引擎以**只读**方式打开语料库；任何「派生索引」都写到别处（`data/vector/`） |
| **写接口只写研究库** | 所有 `POST` 只写 `data/research.db`；语料库**永不写入** |
| **写令牌** | 非回环绑定启动时必须配置至少 32 字符的 `LVC_WRITE_TOKEN`；POST 必须带 `Authorization: Bearer`。代理须与引擎同机、传递 `X-Forwarded-For` 与 `X-Forwarded-Proto: https` |
| **同源校验** | 所有 `POST` 仍检查 `Content-Type: application/json` 与存在时的同源 `Origin`；这是浏览器侧纵深防护，不是身份认证 |
| **幂等键** | 写接口统一 `client_token`，同一 token 重复提交返回**第一次**的结果 |
| **异常细节不回吐** | `500` 只回 `code` + 请求路径；完整堆栈进服务端日志（`LVC_DEBUG=1` 才回吐） |
| **密钥不入库** | 大模型密钥只在本机环境变量 / `solve/data/llm_local.json`（不入仓） |
| **外发边界** | 向量启用且索引/嵌入端点可用时，语义查询词会发往配置的嵌入端点；`LVC_VECTOR=0` 可禁用。大模型说法层另按需调用 |

> 网络访问必须经 HTTPS（Caddy 可自动签发）；Bearer 令牌若经 HTTP 明文传输可被同网段窃取。公网部署还应另加限流与访问控制；
> 大陆公网服务还需域名备案。

## 八、常见问题

| 现象 | 原因 / 处置 |
| --- | --- |
| 本机能开、别人打不开 | ① 没加 `--host 0.0.0.0`；② 未设置 `LVC_WRITE_TOKEN`（非回环监听会拒绝启动）；③ 防火墙没放行；④ 把 `127.0.0.1` 当成了对外地址 |
| 代理下 `/engine/` 404 | `proxy_pass` 末尾少了 `/`（不剥前缀）或多了（重复剥）；见 `deploy/nginx-cilv.conf` 注释 |
| 流式问答卡住不动 | 代理开了响应缓冲——需 `proxy_buffering off;`（配置里已写） |
| `ModuleNotFoundError: pypinyin` | 只有建库 / 答题 / 自检 / 解题链需要；**网页服务不需要** |
| 启动即退出，报「没有找到 corpus.db」 | 语料库没拷过去，或工作目录不对（要在项目目录下启动） |
| 页面显示 NaN / 空表格 | 打开的是旧副本：页脚有「生成时间」探针，没有就是旧的 → `Ctrl+F5` |
| 端口不是 8000 | 被占用后**自动顺延**，以启动日志打印的实际端口为准 |

## 九、附：与另一个应用共存的接口边界（主从式）

主从式下，**两个进程之间只通过 HTTP 通信**，边界如下：

| 方向 | 内容 | 说明 |
| --- | --- | --- |
| 主应用 → 本引擎 | `GET /api/*` | 只读接口，可自由调用（检索 / 问答 / 解析 / 词谱 / 口径对照 / 快照） |
| 主应用 → 本引擎 | `POST /api/*` | 写研究库（摘录 / 事实 / 裁定 / 版本 / 论证稿）；**带 `client_token` 幂等** |
| 本引擎 → 主应用 | 无 | 本引擎**不主动回调**、不依赖主应用 |
| 共享 | `data/corpus.db`（只读） | 若主应用也要用同一份语料，**只读共享**即可，不会冲突 |

> 这样两个应用**可以各自独立部署、独立升级**；任一方挂掉，另一方仍能提供自己的功能。
