# 词律探微 · 项目现状说明书

> **用途**：向技术评审（企业指导老师）完整说明本项目的**设计思路、架构、运行方式、能力边界与风险**，  
> 并列出希望得到指导的具体问题。  
> **版本**：1.0.0 ｜ **成文日期**：2026-10-14 ｜ **语料规模**：58,852 篇 / 420,476 句（清 26,742 · 宋 21,053 · 元 11,057）  
> **一句话**：把清代（及宋元）词作的**声律**做成**可复算的数字**，用检索端**证据与原文**，  
> 大模型只负责**说得通顺**——每处数字都要能被引擎追认。

## 一、它解决什么问题

词学研究里，**声律**（每个字的平仄、每句的字数、句脚字的声调、全篇的平仄配置）  
长期依赖**人工判读**——慢、且难复核。本项目要解决三件事：

1. **算得准**：把声律做成**确定性计算**——同一输入永远同一输出，任何人可独立复算。
2. **说得清**：用大模型把数字**讲成人话**，但**数字只能来自引擎**，大模型不许自己编。
3. **可核验**：每个结论都要能**追到原文与出处**；说不清的就**如实说说不清**，绝不编造。

对应五类功能（榜单要求）：

| #  | 功能   | 本项目实现                                            |
| -- | ---- | ------------------------------------------------ |
| F1 | 逐字研读 | 全量 58,852 篇任意一篇可**逐字解析**（平仄 / 句读 / 字位读音候选）       |
| F2 | 词谱比较 | **词谱对照页**：自动匹配词牌 → 体式切换 → 三行对照（原字 / 谱书规范 / 作品实际） |
| F3 | 论证辅助 | **结构化论证稿**（主张 / 桥梁 / 评估态 / 替代解释 / 缺证）+ 可编辑 + 修订链 |
| F4 | 校订建议 | 校订队列 + 来源准入 + 版本链（人工动作全程留痕、可撤回）                  |
| F5 | 知识图谱 | 作者 / 词牌 / 朝代 / 声情的关系图谱（离线视图 `graph.html`）        |

## 二、总体设计思路（三条链 + 一句口令）

### 2.1 一句口令

> **数字归引擎、文料归检索、说法归生成、出处归引用。**

四件事各有归属，**互不越界**：引擎只算数，检索只找料，大模型只说理，引用只呈现出处。

### 2.2 三条链（**物理隔离**）

```
┌─ 交付链 solve/（答案的唯一来源）─────────────────────────────┐
│  corpus.py → pronounce.py → prosody.py → solver.py            │
│  ★ solver.py **只导入** corpus/pronounce/prosody              │
│  ★ **不导入** ask/retrieve  → 改问答层不可能动交付答案          │
└───────────────────────────────────────────────────────────────┘
┌─ 问答链 solve/（ask.py / retrieve.py / guard.py …）──────────┐
│  理解 → 多路检索 → 计算 → 证据块 → 四道护栏 → 成文            │
└───────────────────────────────────────────────────────────────┘
┌─ 前端 frontend/ + 服务 web/ ────────────────────────────────┐
│  Vue3 视图 + Python 标准库 HTTP 服务（/api/* + 静态页）        │
└───────────────────────────────────────────────────────────────┘
```

**为什么这样切**：交付答案（700/300 两套）是赛题判分的硬基准。  
把它放在**独立、只依赖三个模块**的链里，就获得了**结构性保证**——  
改前端、改问答、改检索，**在物理上不可能**改变交付答案。这不是「小心」，  
是**架构层面的隔离**（决策记录 D07）。

### 2.3 关键取舍

| 取舍     | 选择                                    | 理由                       |
| ------ | ------------------------------------- | ------------------------ |
| 大模型用在哪 | **只用在「说法层」与「问句理解」**                   | 数字必须可复算，不能让模型编           |
| 数据库    | **SQLite 文件库**，不用数据库服务                | 零服务依赖 → 部署极简、信创友好        |
| 后端框架   | **Python 标准库** `http.server`          | 无第三方 Web 框架 → 无供应链风险、易审计 |
| 检索     | **多路（词面/元数据/全文/数值/声律/向量）+ 名次融合**      | 单路召回不全；融合后按名次而非分值，稳健     |
| 护栏     | **四道**（数字有出处 / 引文逐字落地 / 无据即认账 / 边界声明） | 「说得像真的」不等于「是真的」          |

## 四、运行流程

### 4.1 安装（三步）

```bash
# ① 确认 Python
python3 -V            # 需 ≥ 3.10

# ② 依赖（仅建库/答题/自检需要；只跑网页可跳过）
pip install pypinyin

# ③ 启动（默认 127.0.0.1:8000，端口占用自动顺延）
python web/serve.py
```

**离线看效果**（不装任何东西）：双击 `data/vue/index.html` 即可——  
它是**自包含**页面，不联网、不需服务器。

### 4.2 配置（全为可选）

| 变量                                                       | 作用                 | 默认          |
| -------------------------------------------------------- | ------------------ | ----------- |
| `ZAI_API_KEY` / `DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY` | 说法层大模型密钥（**任一即可**） | 不设 = 只用模板作答 |
| `LVC_PLANNER`                                            | 是否启用规划路（多步问句）      | 网页启动默认开     |
| `LVC_VECTOR`                                             | 向量语义检索             | 开（`0` 关）    |
| `LVC_DEBUG`                                              | 是否回吐异常细节           | 关           |
| `LVC_QUESTIONS_DIR`                                      | 题库目录（门禁用）          | 自动探测        |

> **密钥只在本机环境变量或 `solve/data/llm_local.json`（不入仓）**；服务端**只回模型名、不回密钥**。

### 4.3 一次问答的完整链路

```
用户问句
  │
  ├─ ① 理解：规则路 + 大模型路（安全网）→ QuerySpec（朝代/作者/词牌/题名/句脚/数值/声情…）
  ├─ ② 检索：词面 / 元数据 / 全文(FTS5) / 数值 / 声律模式 / 向量  六路并行
  │         └─ 名次融合（RRF）→ 候选篇目
  ├─ ③ 计算：命中篇目的声律指标**由引擎确定性计算**（不是模型算）
  ├─ ④ 证据：组装证据块 [E1][E2]…（含逐句原文与出处）
  ├─ ⑤ 护栏：四道（数字有出处 / 引文逐字落地 / 无据即认账 / 边界声明）
  └─ ⑥ 成文：大模型把「引擎给的事实清单」讲成通顺的话（过护栏才采纳，否则回落模板）
        │
        └─ 返回体附带：执行路径报告（route）+ 结果状态（result_state）+ 护栏结论（verify）
```

### 4.4 构建前端（仅改前端时）

```bash
node frontend/tools/build-all.mjs     # ① Vite 出页面 → ② Python 出数据（顺序不能反）
```

## 六、质量保障体系（这是本项目最硬的地方）

### 6.1 五道关键门禁（统一入口 `tools/check_all.py`）

| 门禁                            | 管什么                         | 当前值                                     |
| ----------------------------- | --------------------------- | --------------------------------------- |
| **A. 双集零回归** `regress.py`     | 公开 700 + 保密 300，**逐字节哈希**比对 | 公开 `BF863368…` · 第二套 `ACEF8B15…` **一致** |
| **B. 程序化自检** `selftest.py`    | 结构 / 安全 / 说法层断言             | **300 项 0 失败**                          |
| **C. 服务端接口** `test_api.py`    | `/api/*`（不起服务、不联网）          | **176 项 0 不符**                          |
| **D. 逻辑层等价** `check-core.cjs` | 前端逻辑 vs 冻结基线                | **213,972 项 0 不符**                      |
| **E. 逐题复核** `verify_1000.py`  | 答非所问 + 准确性 + **条件理解一致性**    | **1000/1000**，条件理解不一致 **0**             |

**附加**：`ssr-smoke` 31/0 · `check-types` 0 错误 · `test_render` 522,242/0 ·  
`verify_views` 43,459/0 · `test_ui` 147/0 · `doc_check` 9/9。

> **为什么「逐题复核」是核心**：只比数字会漏掉「条件听漏、范围不同、胜出者碰巧没变」。  
> `verify_1000` 会把引擎对题目的理解**编译成 SQL 的命中篇数**，与**独立真值**逐题比对——  
> 这是唯一能证明「它真的听懂了题」的尺子。

### 6.2 零回归锚点

- 交付答案 `answers_700.jsonl` 的 SHA256 = `bf863368…ff7d1e`，**与金标逐字节一致**。
- 两道哈希写死在 `solve/data/golden_sha.json`，**门禁只从这一处读**。
- **任何改动**（含问答层、前端）**都不许**动这两个哈希——这是赛题判分的底线。

### 6.3 结构性隔离（为什么敢改）

`solve/solver.py` **只导入** `corpus` / `pronounce` / `prosody`。  
前端与 `web/` 都在交付链之外 → **物理上不可能**影响答案哈希。  
因此「改问答/前端」是**低风险动作**，可以放心迭代。

### 6.4 文档即门禁

`tools/doc_check.py` 校验「README 里写的命令**真的存在、真的能跑**」——  
防止文档承诺与产物漂移。当前 **9/9**。

| **论证稿**   | 结构化（主张/桥梁/评估态/替代解释/缺证）+ 可编辑 + 修订链 + **Word/Markdown 导出** |
| **知识图谱**  | 作者 / 词牌 / 朝代 / 声情的离线关系图                                  |
| **全程留痕**  | 人工动作写**决策事件**，可撤回、可回溯；问答快照可回查（不重算）                       |

## 十二、部署选型：Windows Server 还是国产信创 Linux？

**结论先行**：**两者都能装，且都很简单**；若面向**国产化 / 信创评审**，优先 **openEuler / 麒麟**。

| 维度              | Windows Server          | 信创 Linux（openEuler / 麒麟）                       |
| --------------- | ----------------------- | ---------------------------------------------- |
| **Python**      | 装 3.10+ 即可              | 系统常自带 3.9–3.11；<3.10 需装新版                      |
| **SQLite FTS5** | 官方 Python 自带            | **需确认**（少数发行版未编译 FTS5）                         |
| **中文字体**        | 自带                      | **需装** `wqy-zenhei` / `noto-serif-cjk`         |
| **常驻服务**        | 「任务计划程序」（计算机启动时）        | **systemd**（`deploy/cilv-engine.service` 可直接用） |
| **反向代理**        | IIS / nginx for Windows | nginx / Caddy                                  |
| **适配工作量**       | 低                       | **低**（主要是 3 项「确认」，不是「改造」）                      |
| **评审观感**        | 一般                      | **更契合国产化要求**                                   |

**适配清单（6 项，逐条确认即可）**：  
① Python ≥ 3.10 ② SQLite FTS5 可用 ③ 中文字体 ④ `faiss-cpu` 可选（装不上自动降级）  
⑤ 防火墙放行端口 ⑥ `LANG/LC_ALL` 为 UTF-8。

**一键自检**（部署后先跑）：

```bash
python tools/check_all.py --fast      # 交付答案哈希 + 自检（约 10–20 秒）
python web/serve.py --port 8010 --no-open &
curl -s http://127.0.0.1:8010/api/examples | head -c 120
```

**三种部署形态**：A 单机直连（本机用）· B 局域网共享（内网/VPN）· **C 主从式（推荐对外服务）**——  
本引擎只绑 `127.0.0.1`，由反向代理按 `/engine/` 前缀转发，**与其它应用各用各的端口与数据，  
可独立部署、独立升级**。配置见 `deploy/nginx-cilv.conf`、`deploy/cilv-engine.service`。
